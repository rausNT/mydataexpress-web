# DataExpress Web: открытая модернизация сервера и совместимость расширений

Здравствуйте!

Мы начали публичную модернизацию DataExpress Web Server. Цель проекта — сделать
понятную веб-версию, в которую можно загрузить существующую базу DataExpress и
открыть её в браузере без ручной настройки сервера. Главный приоритет —
совместимость существующих и новых расширений `.epas/.wepas`, включая модули,
которые сейчас зависят от Windows API, DLL, COM/OLE и настольного интерфейса.

Это независимая экспериментальная работа на основе открытых исходников Павла
Дуборкина. Проект не является официальным облачным сервисом DataExpress.

## Что уже сделано

- Создан публичный репозиторий:
  <https://github.com/rausNT/mydataexpress-web>
- Подготовлена установка на чистую Ubuntu одной командой:

  ```bash
  curl -fsSL https://raw.githubusercontent.com/rausNT/mydataexpress-web/main/deploy/install.sh | sudo bash
  ```

- Развёрнут рабочий демонстрационный сервер:
  <http://74.208.142.118/>
- Реализована загрузка через браузер файлов `.DXDB`, `.FDB` и официальных
  `.DXDB.zip`, а также отдельная загрузка комплектов шаблонов.
- Добавлена автоматическая проверка Firebird, перенос старых ODS 11/12 в
  Firebird 5 ODS 13 и обновление необходимых служебных таблиц DataExpress.
- На сервер добавлены официальные демонстрационные базы и 29 бесплатных баз из
  раздела форума. На главной указаны понятные названия, описания и найденные
  авторами демо-логины.
- Установлены найденные комплекты DOCX/DOCM/XML/ODT/ODS/HTML-шаблонов.
- Исправлена часть проблем старой вёрстки: высоты элементов, наложение полей,
  отображение списков и обновление статических ресурсов.
- Добавлены изолированные по конкретной базе `.wepas`, явное назначение
  проверенной версии `DX_PLUS_WEB`, аудит функций и действий расширений и
  инструменты миграции `.epas` в веб-модули. Общий автоматический каталог
  отключён: в DataExpress нет надёжного контроля версий расширений.
- Настроены Nginx, UFW, Fail2ban, ограничение частоты запросов, автоматические
  security-обновления, изоляция системных служб и техническое логирование.
  Для защиты от злоупотреблений журналируются IP-адрес, время, идентификатор
  запроса, метод, путь без query-параметров, статус, объём, длительность и
  User-Agent. Тела запросов, пароли и ключ администратора в обычный access-log
  не записываются; стандартный срок хранения — до 30 суток.
- Настроена CI-проверка Linux- и Win32-сборок. Автоматические тесты проверяют
  сервер, загрузчик баз, миграцию расширений, provider API и веб-интерфейс.

Демо-сервер предназначен только для учебных и проверочных данных. Перед
использованием следует ознакомиться с полными правилами:
<http://74.208.142.118/html/demo-terms.html>. Запрещены реальные персональные и
медицинские данные, незаконная деятельность, обмен сообщениями и файлами между
пользователями, попытки взлома и создание помех работе сервера.

## Честный текущий статус расширений

Проект пока не объявляет «поддерживаются все расширения». Например, проверка
реальной стоматологической базы сейчас обнаруживает:

- 33 функции расширений, из них готовых веб-реализаций — 0;
- 86 действий расширений, из них готовых веб-реализаций — 29.

Остальные модули не скрываются и не считаются рабочими формально: сервер
показывает точный список отсутствующих реализаций. Среди найденных зависимостей:
`BtnMLCaption`, `DRTS`, `exec_act`, `j_module`, `MenuItem`,
`RecordEditor`, `SirWolf_module`, `SMART`, `Color Field`, `Export Excel` и
другие.

Именно устранение этого разрыва — задача № 1.

## Как планируется поддержать Windows-зависимые модули

Сейчас проверяется гибридная схема:

1. Переносимый код исходного `.epas` автоматически пробуется в штатном
   PascalScript Web Server без переписывания алгоритма.
2. Браузерные действия получают адаптер веб-интерфейса вместо настольных окон и
   модальных диалогов.
3. COM/OLE, WinAPI и настоящие 32-битные DLL направляются в изолированный
   Windows-совместимый исполнитель. Рассматривается Win32-сборка сервера под
   Wine; полноценная Windows-VM оставлена как запасной вариант.
4. После загрузки базы автоматический аудит должен сразу показать, какие
   функции и действия реально компилируются и выполняются, а какие ещё требуют
   адаптера.
5. Новые `.epas/.wepas` проходят тот же автоматический конвейер — без
   необходимости заранее вносить имя каждого модуля в код сервера.

Важно: одна только установка Windows или Wine не превращает настольный
интерфейс в браузерный. Официальный Web Server использует отдельный API и
сопоставляет функции по имени, а действия — по GUID. Поэтому для полной
совместимости нужны одновременно автоматический компилятор, адаптер интерфейса
и Windows-исполнитель для действительно платформенных вызовов.

## Какой ИИ участвует в разработке

Кодовую базу исследует и модернизирует агент OpenAI Codex на базе GPT-5. Он:

- анализирует исходники DataExpress и документацию;
- пишет код, миграции, тесты и документацию;
- собирает Linux- и Win32-версии через CI;
- разворачивает проверенные изменения на тестовом сервере;
- запускает smoke-тесты баз и анализирует журналы ошибок.

ИИ не является владельцем проекта и не принимает юридические или продуктовые
решения вместо человека. Изменения публикуются открыто, проверяются тестами и
могут быть независимо просмотрены в GitHub.

## Как можно помочь

Особенно нужны:

- `.epas`, `.wepas` и связанные DLL, которые используются в реальных базах;
- ссылка на тему и версию расширения;
- небольшая тестовая база без персональных и коммерческих данных;
- точные шаги: форма, кнопка или выражение, ожидаемый результат;
- информация об условиях распространения модуля и DLL;
- готовые официальные веб-модули авторов расширений.

Не присылайте базы с реальными пациентами, сотрудниками, платежами, паролями,
медицинской тайной или другими персональными/конфиденциальными сведениями.
